# Development roadmap

1. **Blank terminal → demo.** Install Rust, Node 22 and native Tauri prerequisites. Clone this repository, run locked core tests, `npm ci` in `apps/desktop`, then `npm run tauri dev`. Verify the demo channel and all themes, including JSON import, keyboard focus, resizing and reduced transparency.
2. **Bot sandbox → messaging.** Create a dedicated bot and test server, configure intents and least-privilege permissions, inject its token only into the native backend. Confirm READY/guild/channel population, fetch history, send text and receive it through the Gateway. Confirm 403 errors are understandable and no token reaches DevTools. Test message edit/delete and reconnect in the sandbox.
3. **Protocol hardening.** Expand local fake-peer tests for invalid sessions, fatal close codes, server heartbeat requests and overload. Add injectable HTTP transport/base URL for scripted 429/global bucket tests. Implement identify/session quotas, per-bucket REST limits, graceful stop/sign-out and cancellation; replace raw transport with a maintained bot library if that reduces risk.
4. **Correct state under load.** Reconcile REST/live messages in stable snowflake order, add request generation IDs, filter channel permissions, and implement bulk delete, threads and pagination. Move to per-channel versioned patches and virtualized/keyed lists. Validate backpressure and no data loss under bursts.
5. **Desktop product.** Add OS keychain credential entry, clear data on sign-out, native menus/shortcuts, screen-reader/IME/keyboard tests, system-theme sync and contrast checks. Add sanitized Markdown, attachment limits and persistence only behind explicit privacy controls.
6. **Performance gate.** Profile release builds on real Windows and macOS machines. Compare whole-process-tree RSS/working set, idle CPU, startup time and p95 input latency against the official client under the same workload. Test cache eviction, minimized/background behavior and long sessions. Set measured budgets before claiming a performance improvement.
7. **Distribution.** Run native Windows and both macOS architectures in CI. Produce unsigned test installers first; then configure code signing, notarization and tested update rollback. Test installation/uninstallation on clean machines, including WebView2 provisioning and macOS quarantine/Gatekeeper. Publish a DMG and optional Homebrew cask only after those checks.

The repository implements the foundational parts of steps 1–2; it does not claim completion of the later gates. Real bot messaging still requires an authorized bot token and live validation.
